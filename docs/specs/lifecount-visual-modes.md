# LifeCount 人生视觉模式 Spec

状态：待实现

来源：LifeCount 视觉模式调研、GitHub 仓库复用调研及已确认的单一高层 seam。

## Problem Statement

LifeCount 当前主要通过日、周、月、年方块网格表达从出生日期到最高年龄之间的人生进度。这个视图适合精确查看人生阶段、典型事件和已过去的时间，但不提供连续的、具有象征性的视觉表达。

用户希望在 header 设置按钮左侧增加一个入口，在不破坏现有方块网格和设置弹窗的前提下，将同一份 Me 设置数据表达为三种新的视觉视图：沙漏、蜡烛和天光。

当前风险有三类：

- 如果每个视图自己读取出生日期、最高年龄或预设，会出现不同视图显示不同人生进度的问题。
- 如果把每一秒都当成真实渲染粒子，几十年的人生区间会产生不可行的粒子数量。
- 如果为了视觉效果直接引入 three.js、PixiJS、Rapier 或 A-Frame，会把完整 demo 的运行时和生命周期带入当前 Astro 页面。

## Solution

在 header 设置按钮左侧增加“人生视图”入口。点击后打开与现有设置风格一致的非阻塞弹窗，用户可以在四种视图之间切换：

1. 方块网格：保留当前 LifeCount 主视图。
2. 沙漏：上方表示剩余寿命，下方表示已经过去的寿命。
3. 蜡烛：已经燃烧的寿命对应已消耗的烛身，剩余烛身对应未来寿命，两侧显示有限的蜡流。
4. 天光：使用浏览器当前本地时间表达凌晨、清晨、上午、正午、下午、傍晚和夜间。

所有视图通过唯一的 `VisualModeController` 读取现有 `MeSettings`，并消费统一的 `TimeSnapshot`。现有方块网格继续作为精确信息视图，新的视图作为表达时间感受的补充。

```text
LifeCount 页面
├── Header「人生视图」按钮
│   └── VisualModeDialog
│       └── VisualModeController
│           ├── GridRenderer
│           ├── DaylightRenderer  (CSS/SVG)
│           ├── CandleRenderer    (SVG/CSS)
│           └── HourglassRenderer (Canvas 2D)
└── 现有设置弹窗与方块网格

MeSettings → TimeSnapshot → 当前 renderer
```

首版不增加 three.js、PixiJS、Rapier、A-Frame 或 GSAP。后续真实日照功能可以单独评估 `SunCalc`；只有真实设备证明 Canvas 2D 粒子不足时，才重新评估 PixiJS。

## User Stories

1. 作为 LifeCount 用户，我希望在设置按钮左侧看到一个“人生视图”按钮，以便快速切换人生的不同表达方式。
2. 作为中文用户，我希望按钮和弹窗使用中文标签，以便理解当前功能。
3. 作为英文用户，我希望按钮和弹窗使用英文标签，以便在英文页面中完成相同操作。
4. 作为用户，我希望点击人生视图按钮后看到一个选择弹窗，以便明确选择目标视图。
5. 作为用户，我希望弹窗显示“方块网格、沙漏、蜡烛、天光”四个选项，以便知道当前可用的视图。
6. 作为用户，我希望当前选中的视图有清晰的选中状态和右侧勾选标记，以便知道当前正在查看哪一种视图。
7. 作为用户，我希望选择视图后弹窗关闭或切换到对应内容，以便立即看到结果。
8. 作为用户，我希望关闭弹窗后现有方块网格的设置、注释、时间单位和语言状态保持不变，以便视图切换不会重置页面。
9. 作为用户，我希望沙漏顶部显示从当前时刻到最高年龄终点的剩余时间，以便理解未来还有多少时间。
10. 作为用户，我希望沙漏底部显示从出生日期到当前时刻已经过去的时间，以便理解已经走过多少时间。
11. 作为用户，我希望沙漏的真实秒数来自同一套人生时间计算，以便它与方块网格的进度一致。
12. 作为用户，我希望沙漏不会尝试创建与真实秒数相同数量的粒子，以便页面在长寿命区间和移动设备上仍然可用。
13. 作为用户，我希望沙漏在弹窗关闭时停止动态粒子，以便打开设置或浏览页面时不会持续消耗资源。
14. 作为用户，我希望蜡烛的燃烧比例与人生进度一致，以便烛身能直观表达已经过去和剩余的寿命。
15. 作为用户，我希望蜡烛两侧出现有限且稳定的蜡流，以便视觉上有燃烧痕迹，同时避免随机刷新后完全改变形态。
16. 作为用户，我希望蜡烛在生命周期接近结束时保留烛台或烛芯等最低可视结构，以便视图不会突然消失。
17. 作为用户，我希望天光根据当前本地时间变化，以便凌晨、正午和夜间的颜色符合我当前设备的时间。
18. 作为用户，我希望天光在不同时间阶段之间平滑过渡，以便颜色不会突然跳变。
19. 作为用户，我希望天光首版不强制请求地理位置权限，以便打开页面时不会被定位流程打断。
20. 作为用户，我希望在没有真实日照数据时仍然看到稳定的固定时钟天光，以便功能不依赖网络或定位服务。
21. 作为用户，我希望修改出生日期后重新打开人生视图时，沙漏和蜡烛使用新的时间数据，以便设置立即生效。
22. 作为用户，我希望修改最高年龄后重新打开人生视图时，剩余寿命和燃烧比例随之改变，以便视图反映新的目标。
23. 作为用户，我希望人生视图的最后选择在同一台设备重新打开页面后保留，以便不必每次重复选择。
24. 作为用户，我希望页面切到后台后不会补播几小时的粒子或火焰动画，以便回到页面时仍然平稳。
25. 作为键盘用户，我希望能通过 Tab、Enter、Space 和 Escape 操作入口、弹窗和视图选项，以便不依赖鼠标。
26. 作为屏幕阅读器用户，我希望每种视图都有等价的文本摘要，以便不需要理解 Canvas 或装饰性 SVG 才能获取人生进度。
27. 作为有减少动态效果偏好的用户，我希望沙漏停止粒子、蜡烛停止火焰摆动、天光保留静态颜色，以便页面尊重系统设置。
28. 作为移动端用户，我希望弹窗和视觉区域在窄屏下不溢出页面，以便可以继续关闭、切换和读取数据。
29. 作为用户，我希望切换视图不会影响现有名人履历、典型人生阶段和注释栏，以便新功能与当前信息层相互独立。
30. 作为维护者，我希望所有 renderer 都消费同一个时间快照，以便未来增加其他人生视图时不会复制业务计算。

## Implementation Decisions

- 新增一个 header 级“人生视图”入口，位置固定在设置按钮左侧，沿用现有 header 控件的字体、圆角、间距、箭头和选中状态规范。
- 新增一个独立的视觉模式弹窗。弹窗使用当前页面的面板材质和交互约定，默认不增加灰色遮罩，不阻塞页面滚动；打开弹窗时只管理自身的焦点和点击区域。
- 弹窗中使用四个模式选项：`grid`、`hourglass`、`candle`、`daylight`。选项采用统一的自定义选择菜单风格，勾选标记统一显示在文字右侧。
- 选择结果保存为视觉偏好，默认模式为现有 `grid`。保存只影响视图选择和必要的视觉偏好，不复制或重写现有 Me 设置缓存。
- 只有一个 `VisualModeController` 负责打开、关闭、切换 renderer、订阅 Me 设置变化、管理动画调度和释放资源。切换模式前必须销毁上一个 renderer 的定时器、rAF、事件监听和 Canvas/SVG 资源。
- 现有 Me 设置是唯一输入源，包括出生日期、最高年龄、国家、模板和当前设置状态。视觉模式首版不支持直接编辑这些字段。
- 新增统一的 `TimeSnapshot` 派生数据。它至少包含总时间、已过去时间、剩余时间和 0–1 人生进度。具体日期边界沿用现有 LifeCount 的周年和日期规则；日期型生日首版按时间轴所在日期的起点处理，不新增出生时刻或地理时区设置。
- 方块网格继续使用现有 renderer。视觉模式 controller 只负责在视图层中切换展示，不改变网格列数、注释轨道、阶段列表或现有预设数据。
- 沙漏使用原生 Canvas 2D 绘制玻璃内部的静态沙堆和有限数量的动态粒子；SVG 或 CSS 负责外轮廓和可访问文本。真实秒数只参与 `TimeSnapshot` 和目标进度计算，不能一秒对应一个 DOM 或物理粒子。
- 沙漏默认采用固定粒子池。标准画质从约 300–800 个可见动态粒子开始，使用真实设备测试调整；当弹窗关闭、页面切后台或系统要求减少动态效果时停止粒子循环。
- 沙漏的长期沙堆比例严格由人生进度决定，局部落沙只作为感知动画，不允许因为动画速度而改变真实进度。
- 蜡烛使用 SVG + CSS。烛身高度由人生进度派生，火焰和蜡流为装饰性动画，蜡流使用固定或基于稳定 seed 的有限路径，确保相同设置和相同进度下形态可重复。
- 蜡烛首版不引入真实物理模拟，不承诺燃烧蜡液体积守恒；蜡流只是已过去寿命的视觉痕迹。
- 天光使用 CSS 渐变和少量 SVG 图层表达天空、太阳/月亮、星光和地平线。首版以当前设备本地钟表时间作为输入，使用多个时间关键帧和连续颜色插值。
- 天光首版不请求地理位置、不使用 IP 推断位置、不展示真实天气。后续若需要真实日照，单独引入 `SunCalc` 和明确的城市或位置设置。
- 时间数字约 1Hz 更新。沙漏动态粒子目标约 30 FPS。蜡烛火焰目标约 15–30 FPS，但优先使用 CSS。天光不使用持续高频 rAF，按分钟或较低频率刷新即可。
- 页面进入后台时暂停装饰动画；回到前台时直接读取当前时间重新计算快照，不补播离开期间的运动。
- 支持 `prefers-reduced-motion`。减少动态效果时保留静态沙堆、静态蜡烛几何和当前时间对应的天光颜色，同时保留文本数据。
- 每种非网格视图都提供独立的可访问文本摘要：沙漏提供已过去和剩余时间，蜡烛提供已过去和剩余比例，天光提供本地时间、当前阶段和使用的时间规则。
- Canvas 和装饰性 SVG 标记为非语义视觉层，真实数据使用稳定的 DOM 文本承载，不让屏幕阅读器每秒播报秒数变化。
- 视觉弹窗使用响应式宽度。桌面端保持适合视图预览的固定最大宽度，窄屏下收缩到视口内；不改变现有设置弹窗的宽度和布局。
- 首版不复用没有明确许可证的 PixelGlass 或未完成蜡烛实验代码，不复制 GPL-3.0 的 daylight-clock 代码，不将旧版 three.js、A-Frame 或桌面应用代码带入主页面。
- 允许后续在单独变更中引入 `SunCalc`；允许在真实设备性能证据证明 Canvas 2D 不足后重新评估 PixiJS。此 spec 不授权引入这些依赖。

## Testing Decisions

- 测试以真实浏览器端到端行为为主，只验证用户能看到、操作和读到的结果，不测试 Canvas 内部某个粒子的坐标或具体 DOM 实现细节。
- 最高测试 seam 是 LifeCount 页面本身：从页面加载开始，贯穿 Me 设置、视觉模式入口、视图切换、缓存、响应式和动画生命周期。
- 首次进入页面时验证 header 按钮位置、可见文本、中文/英文标签、键盘可达性和默认方块网格状态。
- 打开视觉弹窗后验证四个视图选项、当前选中状态、右侧勾选标记、点击切换、Escape 关闭和焦点返回入口。
- 修改出生日期和最高年龄后分别打开沙漏与蜡烛，验证文本摘要和比例随设置改变；不要求通过截图判断每个 Canvas 像素。
- 切换天光视图时使用可控的浏览器时间或页面时间适配方式，验证凌晨、正午、傍晚和夜间关键阶段的颜色阶段与文本阶段正确。
- 验证设置弹窗关闭和重新打开后，视觉模式仍然读取最新 Me 设置；验证页面重新加载后视觉模式偏好从缓存恢复。
- 验证切换到后台再返回时，时间快照跳到当前时间，页面不会补播长时间动画；关闭视觉弹窗后不再有持续动画循环影响页面。
- 验证 `prefers-reduced-motion` 下三种视图仍有静态内容、文本摘要和可操作控件，但不持续播放装饰动画。
- 验证桌面宽屏、窄窗口和移动尺寸下弹窗不溢出，视觉区域和关闭控件可见，现有方块网格宽度与注释栏逻辑不被改变。
- 验证现有语言、日/周/月/年、国家、模板、典型人生事件、名人去世时间、名人履历和注释交互在新增入口后仍然可用。
- 验证未来生日、最高年龄较小、人生进度为 0%、接近 100% 和已超过终点等边界状态下，沙漏、蜡烛和文本摘要不出现负数、NaN 或空白。
- 性能验收关注外部行为：视觉弹窗关闭时无活跃高频循环；标准沙漏视图在目标桌面浏览器和移动设备上保持可用交互；连续切换模式不会导致页面逐次变慢或明显增加内存。
- 现有项目的 `check`、`build` 和 `git diff --check` 继续作为静态门槛；功能验收以真实浏览器 E2E 和可复现截图/测量结果为准。
- 不新增只镜像实现细节的单元测试。若某个纯日期边界无法通过页面行为可靠验证，先在 E2E 流程中暴露可读的摘要状态，再决定是否需要补充更高层测试 seam。

## Out of Scope

- 不重构现有方块网格、注释轨道、注释圆点、侧栏或设置弹窗的信息结构。
- 不把现有设置弹窗改成视觉模式弹窗，也不把侧栏改成弹窗。
- 不在本 spec 中新增名人履历的沙漏、蜡烛或天光视图；视觉模式首版只基于 Me 设置。
- 不新增出生时间、出生地、居住地、时间轴时区或经纬度字段。
- 不请求浏览器地理位置权限，不通过 IP 推断精确位置，不实现真实天气或真实星图。
- 不引入 three.js、PixiJS、Rapier、A-Frame、GSAP、Lottie 或其他渲染引擎作为首版运行时依赖。
- 不实现真实颗粒碰撞、3D 玻璃折射、物理蜡液、烟雾物理或可旋转 3D 沙漏。
- 不实现截图分享、全屏沉浸模式、视觉模式自定义主题和高画质档位。
- 不改变现有生命阶段预设、国家教育日历、退休年龄或名人数据。
- 不修改现有设置缓存的数据结构，除非实现过程中证明必须增加独立的视觉模式偏好键。
- 不在本 spec 中发布站点、修改生产环境或提交产品实现代码。

## Further Notes

- GitHub 调研确认没有成熟的、可以同时覆盖三种视图并直接适配当前 Astro 页面的大型组件。复用策略应是“参考算法和结构，自己实现 renderer”，而不是复制完整 demo。
- `SunCalc` 是后续真实日照增强中最适合直接评估的仓库，许可证为 BSD-2-Clause；它只提供日照计算，不提供视觉组件。
- `Hourglass_Fable5` 最值得保留的思想是“墙上时钟决定真实进度，粒子只负责表现”；这个原则比具体的 Rapier 物理实现更适合 LifeCount。
- 视觉模式 controller 是本功能唯一建议新增的高层 seam。renderer 可以拆成内部模块，但不应各自读取 localStorage 或各自定义生日和最高年龄。
- 本 spec 依赖已有 Me 设置和统一日期计算的当前语义。实现前应先确认现有日期边界在秒级视觉展示中的解释，并通过页面摘要让用户能理解“按出生日期估算”的含义。
- 该 spec 已保存为项目文档。当前仓库未配置 `$to-spec` 要求的 issue tracker 和 `ready-for-agent` 标签，因此尚未创建外部事项；配置完成后应将本 spec 原文发布到项目 tracker，并标记为 `ready-for-agent`。
