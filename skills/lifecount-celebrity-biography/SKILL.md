# LifeCount 名人履历 SOP

使用这份 SOP 为 LifeCount 增加一个可核验的名人履历档案。工作结果必须同时满足：资料可追溯、阶段不依赖过密连线、事件数量适合网格展示、未来内容使用中性灰色、侧边栏能够解释色块。

## 1. 先建立研究清单

为每个人先收集以下字段：

- `birthDate`、出生地、必要时的 `deathDate`。
- 教育和早期经历：学校、大学、转学、毕业或退学时间。
- 连续职业阶段：公司或机构、角色、开始和结束时间。
- 关键事件：成立、上市、产品发布、技术里程碑、收购、重大角色变化。
- 每条记录的 `sourceUrl`、`status`、日期精度和简短展示文本。

先列候选记录，再决定哪些进入默认展示。默认展示优先覆盖身份转折和公共里程碑。

## 2. 按来源和证据分级

来源优先级：

1. 公司、大学、政府、监管文件、NASA 等一手资料。
2. 本人采访、校友资料、官方传记资料。
3. Reuters、AP、Britannica 等权威媒体或参考资料。
4. Wikipedia 作为索引和交叉核对来源。
5. 单一家庭史、论坛、无原始材料的年表只能生成候选记录。

状态使用：

- `verified`：日期和事实得到一手来源或多来源交叉确认。
- `conditional`：事实可信，但日期、角色或来源口径仍有边界。
- `candidate_only`：只有推断或单一弱来源，默认不展示。

日期精度必须保留：`day`、`month`、`year-only`、`approximate` 或 `disputed`。不把年份补成虚假的月日。

## 3. 生成连续色块

色块表达一条连续的人生阶段时间线。教育经历和职业经历优先进入色块，避免为每所学校和每家公司画一条注释线。

- 不重叠的教育阶段使用不同颜色，例如小学、中学、大学。
- 不重叠的主要职业阶段使用不同颜色，并在侧边栏使用具体机构名称，例如 `Zip2 / X.com / PayPal`、`SpaceX / Tesla`。
- 并行公司无法准确压成单条时间线时，使用一个明确的组合标签，事件中再保留重要里程碑。
- 退休阶段不加入名人履历色块。
- 名人模式中，当前日期之后的格子统一使用灰色；历史阶段颜色只表示已知经历。
- 已故人物如果提供 `deathDate`，死亡之后的未经历区间也应使用灰色或单独的未经历状态。

色块必须覆盖从出生到当前展示上限的连续区间，除非资料明确要求存在未知空档；未知空档使用中性灰色，不用猜测的职业颜色填充。

## 4. 收敛关键事件

默认事件控制在约 8–12 条。优先保留：

- 公司成立或关键创业转折。
- 上市、收购、离开或回归核心机构。
- 代表性产品首次发布。
- 可验证的技术或公共影响里程碑。
- 对人生阶段有明显解释力的毕业、退学或角色变化。

删除泛化事件，例如“进入科技行业”“平台与人工智能阶段”。这些内容属于色块标签，不应再占用单独注释。

每个事件使用简短标题和副信息；副信息包含日期、角色、来源口径或必要的不确定性说明。事件来源图标必须可点击。

## 5. 代码接入规则

在 `src/data/lifecount-biographies.ts` 增加档案：

- `birthDate` 和 `basePresetId`。
- 带中英文名称的自定义 `stages`。
- `specialPeriods` 只保留确实需要连线的非色块区间，通常为空。
- `events` 只放收敛后的关键事件。
- 每条阶段和事件尽量有独立来源链接。

名人模式启用时：

- 国家、案例、性别、设置、典型阶段事件、名人死亡按钮禁用。
- 名人选择器、语言、主题、日/周/月/年切换保持可用。
- 阶段侧边栏继续可打开，但内容改为当前名人的自定义色块阶段。

## 6. 完成检查

研究完成：每条默认记录都有来源、状态和日期精度；候选数据没有混入默认展示。

数据完成：色块阶段连续、没有退休阶段；未来或未经历区间为灰色；事件数量收敛到约 8–12 条。

交互完成：名人开关、选择菜单、生日切换、禁用状态和侧边栏阶段全部可验证。

工程完成：`npm run check` 无错误、`npm run build` 成功，并在日、周、月、年视图验证名人模式。
